# Трёхпальцевый скролл и свайп на тачпаде для Omarchy

Один и тот же жест — три пальца по горизонтали — делает разное в зависимости от
режима тайлинга активного воркспейса:

| Режим воркспейса | Что делает жест |
| --- | --- |
| `scrolling` (лента) | Тянет окна за пальцами, с инерцией |
| `dwindle` / `master` (обычный тайлинг) | Переключает воркспейс влево/вправо |

Плюс к этому отключена доводка ленты до ближайшей колонки, а сам скролл ускорен
в 1.5 раза.

Проверено на Hyprland 0.56.2 / Omarchy 4.5.0-3.

## Что кладём

Всё сводится к одному файлу — `~/.config/hypr/input.lua`. Omarchy подключает его
сам (`require("hypr.input")` в `hyprland.lua`), поэтому импортировать ничего не
надо.

В этой папке:

| Файл | Зачем |
| --- | --- |
| [`input.lua.snippet`](input.lua.snippet) | Готовый блок для вставки в `input.lua` |
| [`install.sh`](install.sh) | Дописывает блок сам (с бэкапом и проверкой) |

### Быстрый путь

```bash
./install.sh
```

Скрипт допишет блок в конец `~/.config/hypr/input.lua`, сделает бэкап рядом,
перезагрузит Hyprland и покажет ошибки, если они появятся. Повторный запуск
ничего не задублирует. На чистой машине сначала запустите Omarchy хотя бы раз,
чтобы файл `input.lua` существовал.

### Вручную

Скопируйте содержимое [`input.lua.snippet`](input.lua.snippet) в конец своего
`input.lua` и выполните:

```bash
hyprctl reload
```

Файл личный: `omarchy update` его не перезаписывает.

## Почему это не делается тремя строчками

Главное ограничение: **слот «N пальцев + ось» вмещает только один жест.** Это не
настройка, а устройство Hyprland — `CTrackpadGestures` ищет жест по паре
(fingers, direction) и на втором выдаёт:

```
hl.gesture: Gesture will be overshadowed by a previous gesture.
Previous HORIZONTAL shadows new HORIZONTAL
```

То есть `workspace` и `scroll_move` на «3 пальца + горизонталь» одновременно
существовать не могут. Поэтому жест приходится перевешивать на лету, вслед за
режимом воркспейса.

Режим читается прямо из воркспейса:

```lua
hl.get_active_workspace().tiled_layout  -- "scrolling" | "dwindle" | ...
```

А перевешивать нужно в четырёх случаях: сменился воркспейс, сменился монитор,
открылся/закрылся special-воркспейс, и — главное — поменялся сам режим
тайлинга. Omarchy меняет режим через workspace rule, а правка правила поднимает
событие `config.props_refreshed`. Отсюда список подписок в коде.

### Две ловушки, на которые легко напороться

**1. `scale` входит в «личность» жеста.** Hyprland сравнивает его при поиске
наравне с пальцами и направлением, поэтому `unset` без `scale` не находит жест,
зарегистрированный с `scale`:

```
hl.gesture: Can't remove a non-existent gesture
```

Если дописать `scale` только в регистрацию, переключение режима сломается тихо:
старый жест не снимется, новый не встанет из-за перекрытия. Поэтому в коде и
установка, и снятие идут через одну функцию `swipe_spec()`.

**2. `pcall` не ловит ошибки `hl.gesture`.** Они уходят не в Lua, а в отдельный
канал и видны в `hyprctl configerrors` — прямо пользователю в баре. Так что
защищаться через `pcall` бесполезно; вместо этого код помнит, какой жест он
поставил сам (`bound_swipe`), и снимает только его.

## Проверка, что всё встало

```bash
hyprctl configerrors        # должно быть пусто
hyprctl getoption gestures:scrolling:move_snap_to_grid   # bool: false
```

Переключите воркспейс в `scrolling` и обратно — ошибок в `configerrors` быть не
должно ни после первого, ни после второго.

Проверить, что жест действительно перевесился, можно «зондом»: попытка занять
слот другим действием падает ровно тогда, когда слот занят ожидаемым.

```bash
# На scrolling-воркспейсе: должно упасть с "overshadowed" (слот держит scroll_move)
hyprctl eval 'hl.gesture({fingers=3,direction="horizontal",action="workspace",scale=1.5})'

# На dwindle: наоборот, должно упасть на scroll_move
hyprctl eval 'hl.gesture({fingers=3,direction="horizontal",action="scroll_move",scale=1.5})'
```

После проверки ошибки из `configerrors` уходят сами при `hyprctl reload`.

## Настройка под себя

| Что | Где | Как |
| --- | --- | --- |
| Скорость скролла | `scroll_swipe_scale` | `1.5` → больше/меньше |
| Доводка до колонки | `move_snap_to_grid` | `true`, если хочется «прилипания» |
| Прыжок курсора после жеста | `move_snap_cursor` | `false`, если курсор мешает |

`scale` действует на весь жест целиком, включая инерцию: на больших значениях
лента улетает дальше, чем ожидаешь.

Без доводки лента может останавливаться между колонками, и окна стоят
обрезанными по краям. Это осознанная плата за свободное позиционирование;
компромисс — оставить доводку, но уменьшить скорость.

## Что осталось на четыре пальца

Четыре пальца по горизонтали всегда переключают воркспейс. На scrolling-раскладке
это нужный выход: иначе сменить рабочий стол, не трогая ленту окон, было бы нечем.

## Известный компромисс

При открытом special-воркспейсе (например qconsole) жест выбирается по **его**
раскладке, а не по тайловой под ним. Причина: special перекрывает экран, и
двигать невидимые окна под ним было бы странно. Если нужно наоборот — в
`swipe_action()` убрать `hl.get_active_special_workspace()` из строки выбора.

## Если что-то пошло не так

- **Жест не работает вообще** — проверьте, что `input.lua` действительно
  подключается: в `hyprland.lua` должна быть строка `require("hypr.input")`.
- **Жест переключает воркспейсы на scrolling-раскладке** — не сработала
  перевеска. Посмотрите `hyprctl configerrors`; если там `overshadowed`,
  значит старый жест не снялся (обычно из-за разошедшегося `scale`).
- **Скролл дёргается / прилипает** — верните `move_snap_to_grid = true` и
  уменьшите `scroll_swipe_scale`.
- **Откат целиком** — удалить блок из `input.lua` и `hyprctl reload`.
